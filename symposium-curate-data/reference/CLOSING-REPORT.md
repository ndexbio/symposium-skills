# The closing report

The run ends with one report. Six sections, in this order, with these headings, every time.

A user who has run this before should find the part they want without reading the rest, and that
only works if it is the same shape each run. Fill the skeleton; do not redesign it.

## The skeleton

```markdown
## What is in the record

<community>, <n> artifacts, gate-accepted.

| Artifact type | Count |
|---|---|
| ScientificPublication | <n> |
| Argument | <n> |
| Data | <n> |

Local copy verifies against the server: <yes, or what differs>.

## What each source became

**Published with an extracted Argument** — <sources, named>
**Published with narrative declared ungroundable** — <sources, named>
**Citation only** — <sources, named, with why each could not be retrieved>

## What the corpus says about the hypothesis

**Cause** — <how well the groundable sources carry it>
**Effect** — <same>
**Rationale** — <same>

<counter-evidence now in the record, named by source>
<any clause the record cannot carry, said plainly>

## Corrections and departures

<what was superseded and why; what was published differently from the review
table; what failed and was recovered — or one line saying none applies>

## Loose ends

<what stayed out, why, and the action that would change it>

## Where it is

<the record and how to browse it; the working file>
```

## What each section is for

**1. What is in the record.** Numbers, not prose. The community it went to, counts by artifact
type, and whether the local copy verifies against the server.

**2. What each source became.** Name the sources in each group. Three totals tell the user how
much was done; names tell them what they can now reach, which is the question they will actually
have.

**3. What the corpus says about the hypothesis.** Measured over the **published, groundable**
sources, which is a smaller set than the review table counted — the sources that are present and
the sources that can ground an Assertion are different populations, and the difference is often
most of the corpus. Name the counter-evidence the record now holds, and name any clause the
record cannot carry.

**Say it plainly when it undercuts the hypothesis.** A corpus whose own contents put the
hypothesis in the minority is a real finding and the most useful thing a run can produce. A report
that softens it has wasted the work, and the user asked for what the literature says rather than
for agreement.

**4. Corrections and departures.** Anything superseded, and why. Anything published differently
from what the review table showed. Anything that failed and was recovered. Where none applies, say
so in a line and keep the heading — a missing section reads as an omission rather than an absence.

**5. Loose ends.** What stayed out and why, each with the action that would change it: a source
needing access the user could supply, works left behind by the scale, a clause that would need
another run.

**6. Where it is.** The record and how to browse it, and the working file. This is the one place
in the run where that belongs — the loop is over, and the user may want to go and look.

## Keep it about the record

How the run went, what was tried, what took a while, what the agent noticed about its own
process — that is the agent's experience rather than the user's result, and it belongs in none of
the six.
